# 本地插件包导入（IPC v1.0）

插件页的「本地插件」标签提供「导入插件」按钮和拖放区域，支持 `.tppkg` 与 `.zip`（扩展名不区分大小写）。`.tppkg` 是使用自定义扩展名的 ZIP 文件，不是可执行安装程序。

## 使用方式

1. 在插件页点击「导入插件」选择一个包，或将一个包拖到本地插件页，无需先配置目录。
2. 插件统一安装到 **`<exe_dir>/plugins/<name>/`**（TimePin 可执行文件所在目录的 `plugins` 子目录），启动时自动创建插件根目录。GitHub 商店安装、手动放置与重新加载也使用这一目录。
3. 导入成功后列表立即刷新，无需重启 TimePin。目录不可写、文件类型不支持、包损坏或清单不合法时，页面给出可见错误提示。请将 portable 版放在当前用户可写的位置；不会静默回退到其他插件目录。

直接将压缩包复制到插件目录不会安装：插件发现只扫描解压后的直接子目录。导入器读取清单的 `name`，不会根据压缩包文件名猜插件名。可以在「设置 → 高级」查看并打开统一插件目录；设置中不再支持添加搜索目录。

**仅导入可信来源的插件。** 同名目录会被替换；包完整校验后，先停止当前插件进程，再切换目录并重新加载管理器。导入期间不能从本地页启动或重试插件。导入本身不会执行插件入口或安装 Python 依赖；依赖仍按现有机制在首次启动时处理。

不再存在多目录优先级。如果统一目录中另一个文件夹也声明了相同 `name`，导入仍将明确报错；请先备份并移走冲突副本后重试。导入器不会删除冲突的用户目录。`recognition` 是内置识别服务的保留目录；本地导入与 GitHub 安装均拒绝该名称（不区分大小写），避免普通插件覆盖识别服务。

## 旧版本迁移（破坏性变更）

升级后，旧的 `<app_data_dir>/plugins`、设置中的自定义插件目录、资源目录及开发态的 `<repo>/plugins` **都不再被扫描**。本次不自动移动或删除任何旧插件，也不合并同名插件；旧 `settings.json` 的 `customPluginDirs` 字段会被忽略，下次保存设置时不再写出。

1. 升级前备份插件与配置，并记录原来自定义目录的位置；退出 TimePin 后复制完整插件文件夹（含清单、入口、素材）到新的 `<exe_dir>/plugins/`。不要直接覆盖目标中已有的同名插件，先分别备份并选择要保留的版本。
2. 一并复制插件依赖的 `_shared/`、`frame_client.py` 等配套文件，或通过原插件包重新导入。
3. 启动后在「设置 → 高级」确认实际插件目录，在插件页点「重新加载」并检查列表。插件路径变化后，Python 隔离环境可能需要重新创建及安装依赖；旧目录不会自动作为回退。

开发时请将仓库 `plugins/` 中需要的内容复制到实际 debug/release 可执行文件旁的 `plugins/`。Windows 默认 debug 路径通常是 `src-tauri/target/debug/plugins/`；使用自定义 Cargo target 目录时以实际 exe 所在位置为准。该规则在开发和发布模式一致，不依赖当前工作目录。

本次目录约定以 Windows portable / per-user 安装为主要场景。macOS 的可执行文件位于 `.app/Contents/MacOS/`，统一目录相应为其中的 `plugins/`，不是 `Contents/Resources/plugins/`；Linux 只读 AppImage 挂载目录也无法创建可写插件目录。这些部署需要使用可写的解包/安装位置并手动放置插件，本次不新增跨平台回退或自动资源复制。

## 支持的包布局

包内必须包含 `plugin.json` 或 `manifest.json`，以及清单所声明的入口文件。清单字段及版本校验遵循[插件协议](plugin-protocol.md)。优先使用 `plugin.json`，不存在时才读取 `manifest.json`。

支持两种布局：

```text
# 直接位于 ZIP 根目录
plugin.json
main.py
assets/...

# 或仅包一层目录
my-plugin/
  plugin.json
  main.py
  assets/...
```

不递归猜测任意深度的清单位置，也不支持一次安装多个插件的集合包。包含路径穿越、绝对路径、链接、Windows 非法路径或冲突路径的包会被拒绝。

## IPC

命令名为 `import_plugin`；前端统一通过 `api.importPlugin(source)` 调用：

```ts
// 文件选择与 Tauri 原生拖放：由 Rust 读取本地文件，不额外开放前端 fs 权限。
invoke('import_plugin', {
  schemaVersion: '1.0',
  source: 'C:/packages/my-plugin.tppkg',
});

// HTML File 拖放：FileReader 读取后移除 data URL 前缀，传标准 base64。
invoke('import_plugin', {
  schemaVersion: '1.0',
  source: { base64: 'UEsDB...', fileName: 'my-plugin.zip' },
});
```

`schemaVersion` 省略时兼容默认版本 `1.0`；其他版本被拒绝。成功响应为：

```json
{
  "schemaVersion": "1.0",
  "name": "my-plugin",
  "version": "0.1.0",
  "replaced": false
}
```

失败返回可展示的错误字符串。按钮取消不产生导入或错误。真实 Tauri 窗口保留原生 `onDragDropEvent` 路径入口；WebView2 默认接管系统文件拖放，不能仅依赖 HTML `onDrop`。HTML File/base64 分支作为支持 HTML 拖放的 WebView 环境的兼容路径，不表示浏览器预览获得了本地安装权限。

## 安全与恢复边界

- 压缩包最大 128 MiB，单个文件最大 128 MiB，总展开最大 512 MiB，最多 10,000 个归档条目。base64 解码前进行编码长度预检；ZIP/ZIP64 元数据在归档索引分配前受检，防止伪造条目数造成过量分配。
- 包先在目标目录内的 `.timepin-installs/` 下独立暂存和完整校验，再切换到目标插件目录；清单无效或入口缺失不会破坏已安装版本或停止插件。
- 更新先备份旧目录；激活失败尝试恢复，避免「先删除旧版本再发现新包不可用」。暂存和备份不作为插件被扫描。成功覆盖后，旧版本保留在 `.timepin-installs/<事务 ID>/backup/`，**不会自动清理，且暂无界面恢复入口**；确认新版本可用后，可手动删除该事务目录释放空间。手动恢复前退出 TimePin，并将备份移回原插件位置。
- 插件名必须符合现有清单名称规则，安装目标及其祖先不得是链接；同进程的本地导入与 GitHub 安装激活协调串行化，插件启动与重载的切换阶段互斥。不提供跨应用进程的文件锁，不要同时使用多个 TimePin 实例写同一插件目录。
- 停止插件不会强行抢占已进入的长 RPC；正在运行的任务结束并释放进程锁后才会切换目录，因此导入可能等待当前任务完成，而非固定在几秒内结束。
- Unix 普通文件只恢复安全的可执行权限，不恢复归档的 setuid/setgid/sticky 或宽松写权限；目录始终保持可遍历。
- 导入不修改源包或原始视频。插件进程隔离不等于操作系统沙箱，校验通过也不构成对第三方代码的安全背书。
